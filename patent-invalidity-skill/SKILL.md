# 专利无效检索 SKILL

回答一个问题：**这份专利的哪几项权项能被无效掉、用什么证据组合**。只就证据论证据——目标专利自身的文本缺陷（26.3 / 26.4 / 33）不在本技能范围，见下"范围边界"。

## 定位

| 维度     | 说明                                                                                    |
| -------- | --------------------------------------------------------------------------------------- |
| 时机     | 授权之后，多在侵权纠纷、许可谈判、被诉应对中                                            |
| 目的     | 找证据请求宣告无效；或评估稳定性作为谈判/应诉筹码                                       |
| 起点     | **目标专利的权利要求**（不是说明书，不是摘要）                                          |
| 检索要求 | **求准**：每条证据都落到"覆盖哪些特征、如何拼成完整覆盖"，追求单篇 X 类或最短组合链     |
| 产出     | 对比文件证据清单 / 稳定性分析报告                                                       |
| 服务法条 | 22.2（新颖性）、22.3（创造性）、22.4（实用性，少见）                                    |
| 不涉及   | **文本缺陷类理由**（26.3 / 26.4 / 33）、**9 条重复授权**、25 条客体问题——见下"范围边界" |

## 范围边界（不做什么）

本技能只回答一个问题：**手上有没有证据、证据够不够把这项权利要求打掉。** 以下事项不在范围内，不评价、不写论证、不写入报告：

| 排除事项                                                             | 为什么排除                                                                                       |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **26.3 公开不充分**、**26.4 得不到支持 / 不清楚**、**33 修改超范围** | 靠专利文本自身即可主张，不需要检索；判定要逐段核对说明书、实施例与审查档案，属独立的文本缺陷审查 |
| **9 条重复授权**                                                     | 需同族 / 平行专利的权项逐对比对，本质是范围比对而非检索                                          |
| **25 条客体、5 条违反法律公德**                                      | 权项文字即可判断，与检索无关                                                                     |

遇到这些方向时的处理：

1. **只作一句话提示**，例如"另可考虑 26.4 支持问题，本报告未展开"——不写论证、不下结论、不给成案可能性评级；
2. 用户明确要求一并评估时，说明**超出本技能范围**，提示另起任务处理（另有一套文本缺陷审查的方法与流程），不在本报告内混写；
3. 报告"局限与声明"里写明本报告未评价文本缺陷，避免读者误以为已经排除。

为什么必须切干净：证据类结论与文本类结论的**论证结构不同**——前者要"文献 + 段落号 + 结合动机"，后者要"权项与说明书内部对照"。混在一份报告里，读者分不清哪条有证据支撑；更实际的是，文本类理由常被当成"稳赚的附加理由"列上一堆，反而稀释了主攻方向的力度，也让对方在口审时容易把讨论引到无关战场。

## 一、时间界限与证据资格（先定这个）

必须先确定目标专利的**申请日**；有优先权且优先权成立的，以**优先权日**为准。优先权是否成立本身要核实（首次申请文件是否支持后一申请的权利要求），不能想当然。

**基准日可能是逐项不同的——部分优先权必须逐项核。** 一项在先申请只对"已记载于该在先申请文件中的技术方案"产生优先权效力。同一件专利里，权 1 的方案若完整记载于优先权文件，享优先权日；权 3 新增的那组参数若未记载，该权项的基准日就是**实际申请日**。做法：

1. 调取优先权文件（首次申请文本），逐项权项比对：该权项的全部技术特征是否被在先申请文件**直接、毫无疑义地**记载；
2. 凡有一项权项不享优先权，就存在**两个基准日**——后续检索、公开时间分类、抵触申请判定全部按"该项权项自己的基准日"分别执行，不得用一个日期统管；
3. 报告头给"各权项基准日表"（权项 / 基准日 / 依据 / 是否享优先权），仅当全部权项同日时才能简化为单一日期。

这一步的杠杆很大：未享优先权的权项，其基准日更晚，落入"现有技术"范围的文献更多——**往往是被忽略的那条命门**。反过来，如果对方主张的优先权不成立，整条防线会整体后移，也常是无效请求里最省力的一击。

| 类别           | 定义                                                                           | 用途                                           | 检索处理                                                                                          |
| -------------- | ------------------------------------------------------------------------------ | ---------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| **现有技术**   | 公开日早于该项权项的基准日（≤ 基准日 −1 天）的公开文献                         | 评价新颖性与创造性                             | 统一 `PBD:[19000101 TO 截止日]`（截止日 = 基准日 − 1 天；无优先权或优先权不成立时基准日即申请日） |
| **抵触申请**   | 申请日早于该日、**公开日不早于**该日的**中国申请**（含进入中国国家阶段的 PCT） | **仅用于新颖性**，不得用于创造性               | `#8`、`#9` 两式不加上限，专门捞此类                                                               |
| **非现有技术** | 两者均晚于该日                                                                 | 不作对比文件（可作译文参考、技术背景，须注明） | 随 `#8`/`#9` 命中，核对阶段剔除                                                                   |

五点容易错的地方：

1. **抵触申请只限中国申请**。外国申请即使申请日在前、公开日在后，也**不构成抵触申请**，只能算非现有技术。这是中国专利法的特有制度，别套用 EPO 的"conflicting application"逻辑。
2. **抵触申请只能打新颖性**。它不能与现有技术组合评价创造性——一旦当成组合文献用，整个证据链会被对方一击即破。并且要求是"**同样的发明创造**"，部分特征重叠不够。
3. **自己的在先申请也构成抵触申请**。法条是"任何单位或者个人"，包含专利权人自己；同一个技术先申请 A、后申请 B，A 在 B 申请日后公开，A 就是 B 的抵触申请。这是实务中最容易被忽略的一类。
4. **宽限期会咬掉一段时间**。若目标专利主张专利法 24 条的宽限期（国家紧急状态、中国政府主办或承认的国际展览会首次展出、规定学术会议首次发表、他人未经同意泄露），且主张成立，则申请日前 6 个月内的相应公开**不构成现有技术**。检索前先查目标专利有没有主张——主张了还照常检索，会检出一批法律上不能用的文献。
5. **公开日的可核查性**。数据库 `PBD` 可能滞后或录入错误，报告中注明。

## 二、可打的证据类理由（先确认打哪些，再动手检索）

无效只能基于法定理由，不能以"写得不好""范围太宽"泛泛主张。开工前先圈定要打的理由，因为它决定要检索什么、要不要调审查档案：

| 理由       | 法条 | 需要的证据                                        | 本文件对应位置                                      |
| ---------- | ---- | ------------------------------------------------- | --------------------------------------------------- |
| 不具新颖性 | 22.2 | 单篇公开全部特征，或抵触申请                      | 第 8 步 / `#1–#10`                                  |
| 不具创造性 | 22.3 | 1篇 + 公知常识或者2–X 篇组合， 结合具有显而易见性 | 第 8 步 / `#11–#18`                                 |
| 不具实用性 | 22.4 | 无法重复实施、违背自然规律                        | 第 8 步（少见，通常不由检索支撑；需实验或原理证据） |

上表就是本技能能处理的全集：**只有需要"找文献、配证据、搭组合"的理由才在这里**。其中 22.2 / 22.3 是主攻，22.4 视案情取舍（多数案件证据不足，勉强主张反而削弱整体可信度）。

## 三、流程

### 第 1 步 输入确认（A1–A5，一张确认表收完，可跳过）

| #   | 项       | 说明                                      | 跳过时默认                                               |
| --- | -------- | ----------------------------------------- | -------------------------------------------------------- |
| A1  | 权项聚焦 | 填空：留空 = 全部；填权项号 = 聚焦        | 全部逐项评价；聚焦时重点权项完整评价、其余快速筛查并注明 |
| A2  | 检索深度 | 完整（约 18–42 条）／快速筛查（约 10 条） | 完整                                                     |
| A3  | 数据库   | 自有账号库优先，无则免费公开库            | 有账号用账号库                                           |
| A4  | 语种     | 默认中英，可按证据所在国加德/法/西/日/韩  | 中英                                                     |
| A5  | 交付形式 | Markdown（默认）／docx／PDF               | Markdown                                                 |

### 第 2 步 目标专利分析

- **著录与法律状态**：申请号/申请日、优先权（含优先权文件**逐项**核对、优先权是否成立的结论、**各权项基准日表**）、**是否主张 24 条宽限期及主张依据**、授权公告日、预计届满日、年费缴纳、同族清单、既往无效/异议记录——注明数据源与查询日期。被部分无效的权项不必再评价。
- **方案概述**：背景、问题 Q1–Qm（引说明书原文）、方案、效果；
- **权利要求逐项拆解**：`C1-1、C1-2…`（C 前位 = 权项号，后位 = 权项内特征序号）。

### 第 3 步 权利要求解释

**原则：通读全文后取最合理含义。** 读完说明书全文（含实施例、定义段）、权利要求书、审查档案后，对每处歧义措辞确定**一个最合理的含义**，作为检索与比对的基准。**同族**授权文本与中文文本的差别，常是权项解释（同一措辞在不同文本下含义不同）的突破口。

对每处歧义记录：措辞原文 / 确定的含义（一句话） / 依据（说明书定义段、实施例、从权区别原则、审查历史） / 对检索用词与比对结论的影响。

**若已知存在平行的侵权程序（或行政裁决、许可谈判中的范围主张），解释口径必须与之协调。** 同一措辞，在侵权比对里主张窄解释（以求不落入保护范围）、在无效程序里主张宽解释（以求覆盖更多现有技术），两案材料一旦互相调取，会构成对自己先前主张的否定，反而坐实"禁止反悔"式的授人口实。做法：先查明本方在侵权程序中的既有主张（起诉状、答辩状、无效答辩意见），无效检索按**同一口径**推进；确实需要不同口径时，在报告第 4 章写明两案口径差异、各自理由与可能被对方援引的风险，由用户决定取舍——**不得默默切换口径**。

### 第 4 步 检索要素表与分类号（S1 确认后才跑检索式）

- E 表四维度：**技术领域 / 技术问题 / 技术手段 / 技术效果**。同一特征在别人的文献里往往只以"问题"或"效果"的措辞出现，只检手段词必漏；
- 自造词、专利权人特殊用语必须配通用同义词；
- 主分类列全 + 相邻分类；降噪写 `NOT`；
- E 表 + 分类号方案交用户确认（S1）后才跑。

详见 [references/search-strategy.md](references/search-strategy.md) §1–§2。

### 第 5 步 按思路铺开检索

全表统一编号 `#1–#18`，先按新颖性思路（找单篇 X 类），再按创造性思路；按语种、从权展开时用子编号（如 `#16-1`）。

无效场景的特有约束：**每条检索式必须对应明确的覆盖目标**（覆盖哪几个特征、给哪条权项用）；优先找单篇 X 类，找不到再设计"最少篇数、最短组合链"的组合。

`#8`（申请人+时间窗）、`#9`（时间窗外延）在此**生效**，且不加 `PBD` 上限——它们专门捞抵触申请与非现有技术。

### 第 6 步 补充手段

- **引证追溯**：目标专利的审查引文 + 同族 ISR 引文。审查员筛过的引文命中效率远高于自己跑式；引文间同族关系必须标注（同一发明的多份公开文本只算一篇证据，重复计数会虚增证据强度）；
- **审查档案调取**：不只为了找证据，更为了找**禁止反悔**——授权过程中放弃了什么、陈述了什么，直接决定权项解释的边界；

### 第 7 步 证据整理与定级（D1）

文献编号一律 `D1、D2…Dn` 连续编号，"类别"列用 X/Y/A 表达——编号不带类别含义，**改级时按需调整编号与顺序**（如改级导致排序变化，编号与顺序一并重排）。

- 一览表：D 编号 / 公开号 / 申请人 / 公开日 / 类别 / 涉及特征 / 一句话要点；
- 定级表（**要点前置**）：D 编号 / 公开号 / 申请人 / 公开日 / **要点** / 类别 / 涉及特征 / 定级理由 / 关键段落号；
- 表后写"要点解读"：常规特征（多篇均公开）、命门特征（无一篇完全公开）、组合层数。

### 第 8 步 逐项比对

1. **新颖性**：按**单独对比**原则逐项比对，标准"直接的、毫无疑义地确定"。**以抵触申请主张新颖性的，先按 `comparison-method.md` §3.1 判"同样的发明创造"**——文字不同不等于方案不同，文字相近也不等于方案相同；
2. **创造性**：三步法——最接近文献→ 区别特征与**重新确定的**技术问题 → 是否显而易见。每条组合的理由来源落到段落号，**不接受简单并列**；凡主张"属公知常识"的，须附教科书/工具书等书证（书名、版次、页码），无书证只能作辅助论证；
3. **抗辩预演**：五类抗辩 × 专利权人依据 × 反驳要点。无效是双边程序，只写"我方能赢"没有价值。

### 第 9 步 证据组合取舍

存在多个可行组合时，列**组合对比表**（组合链 / 覆盖特征 / 组合层数 / 各权项杀伤力 / 优劣势），用户选定主推 + 备选后再写结论。仅一个组合时告知"无备选"并说明理由。

### 第 10 步 结论与输出

无效宣告可以只针对部分权项提出（请求宣告一项或多项权项无效），未请求的权项不进入审理范围，我方无须为其准备证据，也不会因该权项的论证薄弱而拖累整体；真实目的可能是压缩保护范围（谈判、规避）。

按 [references/report-template.md](references/report-template.md) 交付，分用途给建议：

- **无效宣告**：主证据组合、从权补充证据、同一理由下的备选组合与其他权项、补充证据方向、审查档案调取；
- **稳定性评估/许可谈判**：哪些权项可作筹码、专利权人最可能退守的权项及预备组合；
- **规避设计**：权项覆盖宽度与规避代价，声明未做 FTO 分析。

## 四、质量红线

1. **两类思路都要铺到**，且**每条检索式都挂到"覆盖哪些特征、给哪条权项用"**——没有靶点的检索式等于没跑。
2. **检索前先查两件事**：优先权是否成立（**逐项核，部分优先权会带来多个基准日**）、是否主张 24 条宽限期。任一成立，检索的时间范围就要相应调整，否则会检出一批法律上不能用的文献。
3. **权项解释单一口径**：一处歧义只定一个最合理含义，写明依据段号；不得在检索里用宽口径、在比对里用窄口径。
4. **抵触申请不组合**：只能评价新颖性；只限中国申请（含 PCT 进入中国）；须为"同样的发明创造"；自己的在先申请也算。
5. **原文检索失败要有补检**：日/韩/西文改用 `AUTHORITY` 限受理局 + 英文词补检。
6. **单篇优先、组合最短**：能找到 X 类就不要做组合；必须组合时，组合是否有启示论证不可省——"两篇文献都公开了这些特征"不等于"应当结合"。
7. **段落号落到具体位置**，日文用【】并注明以数据库全文为准，正式使用前以官方公报核对。
8. **区分"能不能无效"与"有多大概率无效"**：前者是法律判断（特征是否被公开、组合是否有启示），后者还取决于合议组对解释的采纳、证据形式要件、口审表现。两个结论分开写，不要混成一句"胜算较大"。
9. **检索式必须可复现**：每条记录数据库、字段语法、语种、执行日期与命中数，进附录 B。跑不出来的检索式，等于没有做过检索。

## 五、工具与环境约定

- 数据库：①自有账号库（PatSnap / incoPat 等，语法按库适配）；②免费公开库（Espacenet、Google Patents、CNIPA、PATENTSCOPE）。**报告必须注明实际使用的库**，覆盖差异写入局限。示例语法以 PatSnap 为主：`TACD/TAC/AN/IN/APD/PBD/AUTHORITY`、`$PARA/$SEN`。
- 审查档案：CNIPA 专利登记簿与审查过程文件；EP 用 EPO Register / File Inspection；US 用 Public PAIR。取不到时在报告中标注"审查档案未取得，禁止反悔未能核查"。
- 取不到全文时：以摘要 + 段落号引用为准，注明"附图未取得、图为据文字自绘"。
- 外文证据：X/Y 类做中文要点翻译，译文按段落号逐段对照，正式举证使用的译文须达到可提交标准。
